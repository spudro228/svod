# Свод

Личная замена Obsidian. Markdown-файлы остаются на диске и правятся чем угодно,
демон синхронизирует их с твоим сервером, браузер открывает тот же свод
с любого устройства.

Полная спецификация решений, протокола и дизайн-системы — `docs/design.html`
(открывается в браузере: там же живой макет интерфейса и все токены палитры).

## Как устроено демо

Сервер работает в Docker — это то, что потом уедет на VPS.
Демон запускается нативно на машине, потому что inotify через bind-mount
с macOS в контейнер работает нестабильно, да и в реальности демон живёт
рядом с папкой, а не рядом с сервером.

```
   ~/obsidian/Vk                    Docker
   211 .md файлов  ──[ svod ]──▶  [ svodd :8080 ]  ◀──  браузер
   источник правды    демон         блобы + лог + индекс
```

## Запуск

```bash
make up                      # сервер в Docker на :8080
make sync                    # разовая заливка свода
open http://localhost:8080   # открыть клиент
```

Дальше — слежение в реальном времени:

```bash
make daemon                  # правки на диске уезжают на сервер сами
```

Папка свода задаётся переменной `VAULT`:

```bash
make daemon VAULT=~/другой/свод
```

Остальное — `make help`.

## Что уже работает

Этапы 0 и 1 из спеки плюс индекс с этапа 3.

- Первичный обход, `fsnotify`, дебаунс 500 мс, правила игнорирования
- Контент-адресуемое хранилище: блобы по `sha256`, история версий бесплатно
- Монотонный `seq` и лог изменений
- Заливка с `If-Match`; несовпадение даёт `409`, ничего не перезаписывается
- Разбор markdown через goldmark: заголовки, `[[wiki-ссылки]]`, `#теги`
- Бэклинки и полнотекстовый поиск на SQLite FTS5
- Веб-клиент: дерево, чтение, оглавление, ссылки сюда, `⌘K`, `⌘⇧F`, `⌘E`
- Живое обновление вкладки по WebSocket

## Чего ещё нет

Обратной синхронизации (этап 2) — сервер знает об изменениях, но демон их
пока не забирает. Поэтому:

- Правка из браузера не включена намеренно. Сервер её примет, но на диск она
  не приедет, и версии разъедутся. Кнопка `⌘E` показывает исходник, а не правит.
- Конфликтные копии не раскладываются. При `409` демон честно сообщает
  и оставляет файл незалитым, ничего не теряя.

Дальше по плану: этап 2 (`GET /changes`, атомарная запись, гашение эха,
конфликтные копии), затем этап 4 (правка из браузера) и этап 5 (вложения).

## Токен

В демо токен пустой — доступ открыт. На VPS обязательно:

```bash
SVOD_TOKEN=длинная-случайная-строка make up
./bin/svod -vault ~/obsidian/Vk -server https://svod.example.com -token та-же-строка
```

## Разработка

```bash
make run                     # сервер без Docker, на :8080
cd web && npm run dev        # фронт на :5173 с проксированием на :8080
```

Демон держит своё состояние в `.svod/state.db` внутри папки свода —
эту папку стоит добавить в `.gitignore` того репозитория.
