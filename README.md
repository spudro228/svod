# Свод

Личная замена Obsidian. Markdown-файлы остаются на диске и правятся чем угодно,
демон синхронизирует их с твоим сервером, браузер открывает тот же свод
с любого устройства.

Полная спецификация решений, протокола и дизайн-системы — `docs/design.html`
(открывается в браузере: там же живой макет интерфейса и все токены палитры).

## Как устроено демо

Сервер работает в Docker — это то, что потом уедет на VPS.
Демон запускается нативно на машине, потому что inotify через bind-mount
с macOS в контейнер работает нестабильно, да и в реальности демон живёт
рядом с папкой, а не рядом с сервером.

```
   ~/obsidian/Vk                       Docker
   211 заметок + вложения ◀─[ svod ]─▶ [ svodd :8080 ] ◀─▶ браузер
   источник правды          демон       блобы + лог + индекс
```

## Запуск

```bash
make up                      # сервер в Docker на :8080
make sync                    # разовая заливка свода
open http://localhost:8080   # открыть клиент
```

## Новая машина

Скачать весь свод в пустую папку — одна команда:

```bash
svod -vault ~/obsidian/Vk -server https://свод.example.com -token <токен> -clone
```

Качает в восемь потоков; свод в 229 файлов приезжает примерно за секунду.
В непустую папку не полезет без `-force` — на новой машине легко перепутать
каталог и получить конфликтные копии вместо чистой копии.

Дальше запускать без `-clone`, чтобы держать папку в согласии с сервером.

Дальше — слежение в реальном времени в обе стороны:

```bash
make daemon                  # правки на диске и в браузере разъезжаются сами
```

Папка свода задаётся переменной `VAULT`:

```bash
make daemon VAULT=~/другой/свод
```

Остальное — `make help`.

## Что уже работает

Все пять этапов из спеки.

**Наверх.** Первичный обход, `fsnotify`, дебаунс 500 мс, `.svodignore`,
заливка с `If-Match`, надгробия при удалении.

**Вниз.** `GET /changes` по курсору `seq`, подписка на WebSocket
с переподключением и догоном после неё, страховочный опрос раз в полминуты.

**Чтобы ничего не сломалось по дороге:**

- *Атомарная запись.* Временный файл рядом и `rename` — редактор никогда
  не прочитает половину файла.
- *Гашение эха.* Состояние обновляется до `rename`, поэтому файл, приехавший
  с сервера, не уезжает обратно и два демона не гоняют его по кругу.
- *Конфликтные копии.* При `409` серверная версия ложится на канонический путь,
  а локальная — рядом файлом `… (конфликт, мак, 2026-09-02 14:05).md`,
  и уезжает на сервер как обычный новый файл. Не теряется ничего.
- *Спор об удалении.* Если на сервере файл удалён, а локально изменён,
  он остаётся на диске и уезжает наверх заново.

**Хранилище и поиск.** Блобы по `sha256` (история версий получается сама),
монотонный `seq`, история пути через `GET /history`, разбор markdown через
goldmark: frontmatter, заголовки, `[[wiki-ссылки]]`, `#теги`, бэклинки,
полнотекстовый поиск на SQLite FTS5.

**Вложения.** Картинки и PDF синхронизируются наравне с заметками, но не
индексируются. Показываются и через `![[имя.png]]`, и через обычный
markdown; вставка из буфера в режиме правки сохраняет файл в `Вложения/`
и вставляет ссылку.

**Веб-клиент.** Три колонки, обе темы (`⌘⇧L`), дерево, чтение и правка
на CodeMirror 6 (`⌘E`, `⌘S`), оглавление, ссылки сюда, теги, история версий,
`⌘K`, `⌘⇧F`, живое обновление по WebSocket.

**Временные ссылки.** Кнопка «поделиться» выдаёт ссылку вида `/s/<ключ>`,
которая открывает ровно одну заметку и её картинки — без дерева, поиска,
истории и соседних записей. Срок живёт на сервере, ссылку можно отозвать.
Гостю отдаётся отдельная сборка: в ней физически нет кода, умеющего
спросить дерево свода.

**Правка из браузера идёт тем же протоколом**, что и с диска: `If-Match`,
а при `409` — полоса с выбором «сохранить своей копией» или «взять версию
сервера». Молча не перезаписывается ничего.

Что рассматриваем дальше — `docs/планы.md`.

## Claude Desktop пишет прямо в свод

`cmd/svod-mcp` — сервер Model Context Protocol. Claude Desktop сам поднимает
его и общается по stdio; своей логики там нет, только перевод вызовов
инструментов в те же запросы, которыми ходит демон.

```bash
go build -o ~/.local/bin/svod-mcp ./cmd/svod-mcp
```

В `~/Library/Application Support/Claude/claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "svod": {
      "command": "/Users/имя/.local/bin/svod-mcp",
      "env": {
        "SVOD_SERVER": "https://свод.example.com",
        "SVOD_TOKEN": "токен"
      }
    }
  }
}
```

Инструменты: `search_notes`, `read_note`, `list_notes`, `list_recent`,
`create_note`, `append_note`.

Заметка, созданная из Claude Desktop, попадает на сервер, оттуда её забирает
демон — и через секунду она лежит на диске в Obsidian. Отдельная интеграция
с Obsidian не нужна: она уже есть.

Запись бережная: `create_note` не трогает существующий файл, `append_note`
дописывает с хешем текущей версии. Если заметку успели изменить с другой
стороны, сервер откажет, а не затрёт.

## Чего нет и не будет в v1

- **Совместное редактирование** (CRDT). Решение № 1 в спеке, осознанное.
- **Переименование с сохранением истории.** Это удаление плюс создание:
  содержимое не теряется, история по новому пути начинается заново.
- **Граф связей, мобильная вёрстка, офлайн в браузере, сквозное шифрование.**

## Тесты

```bash
go test ./...              # сервер и демон
cd web && npm run e2e      # браузер, настоящий svodd с вшитым фронтом
```

`web/e2e/svod.spec.ts` — пятнадцать сценариев в Chromium против того же
бинарника, что уедет на VPS: чтение и разметка, wiki-ссылки, бэклинки
и оглавление, `⌘K` и `⌘⇧F`, панели и темы, правка с сохранением по `⌘S`
и переживанием перезагрузки, автосохранение при выходе из режима правки,
конфликт с сохранением копией, живой приезд чужой правки, картинки,
статус-бар и история версий.

`internal/local/agent_test.go` — два демона сходятся к одному состоянию,
эхо не рождает лишних версий, одновременная правка даёт конфликтную копию,
удаление разъезжается, локальная правка не теряется из-за чужого удаления,
пути с кириллицей и эмодзи ходят целыми.

`internal/index/index_test.go` — frontmatter, теги и ссылки внутри блоков
кода не индексируются, якоря одинаковых заголовков не сталкиваются.

## Выкладка на VPS

Ansible готовит сервер с нуля и запускает свод в Docker за Caddy
с автоматическим сертификатом:

```bash
cd deploy && cp inventory.example.ini inventory.ini && $EDITOR inventory.ini
cd .. && make deploy-all
```

Подробности, бэкапы и разбор устройства — `deploy/README.md`.

## Токен

В локальном демо токен пустой — доступ открыт. На VPS его ставит Ansible,
и он же нужен демону:

```bash
svod -vault ~/obsidian/Vk -server https://svod.example.com -token <токен>
```

## Разработка

```bash
make run                     # сервер без Docker, на :8080
cd web && npm run dev        # фронт на :5173 с проксированием на :8080
```

Дев-серверу vite нужно разрешить WebSocket с его порта — иначе живые
обновления не подключатся:

```bash
./bin/svodd -origins localhost:5173
```

Во всех остальных случаях список пуст, и соединение принимается только
с того же адреса, откуда отдана страница.

Демон держит своё состояние в `.svod/state.db` внутри папки свода —
эту папку стоит добавить в `.gitignore` того репозитория.

Редактор вынесен в отдельный чанк и грузится только при первом входе
в режим правки: в чтении он не нужен.

### Горячие клавиши

| | |
|---|---|
| `⌘K` | переход по именам заметок |
| `⌘⇧F` | поиск по содержимому |
| `⌘E` | чтение ↔ правка |
| `⌘S` | сохранить немедленно |
| `⌘\` | свернуть дерево |
| `⌘.` | свернуть правую панель |
| `⌘⇧L` | сменить тему |
