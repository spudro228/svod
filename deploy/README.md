# Выкладка на VPS

Ansible готовит сервер с нуля и запускает свод в Docker. Плейбуки
идемпотентны — их можно гонять сколько угодно раз.

## Что получится

```
интернет ──▶ Caddy (80, 443)  ──▶  svodd (только внутренняя сеть docker)
             сертификат сам           данные в /opt/svod/data на хосте
```

Наружу открыты только ssh, 80 и 443. Сам свод не публикует ни одного
порта: до него можно дойти лишь через Caddy. Сертификат Let's Encrypt
выпускается и продлевается автоматически.

Каталог данных лежит на хосте, а не в томе docker — так его тривиально
бэкапить и осматривать, не заходя в контейнер.

## Что нужно заранее

- Сервер с Debian или Ubuntu и доступом по ssh-ключу
- Домен, уже указывающий на этот сервер: без этого Let's Encrypt
  не сможет его проверить
- Ansible на своей машине: `brew install ansible`

## Первый раз

```bash
cd deploy
cp inventory.example.ini inventory.ini
$EDITOR inventory.ini          # адрес, домен, почта для сертификата

cd ..
make deploy-all                # подготовка сервера и выкладка разом
```

Токен доступа генерируется один раз и запоминается в `deploy/.svod-token`
(в git не попадает). Его же нужно передать демону на каждой машине:

```bash
svod -vault ~/obsidian/Vk -server https://свод.example.com -token <токен>
```

## Дальше

```bash
make deploy       # выложить новую версию
make provision    # только переподготовить окружение
make check        # проверить плейбуки синтаксисом, без сервера
```

`make deploy` сам собирает образ и упаковывает его — отдельно `make image`
звать не нужно.

## Откуда берётся образ

По умолчанию `svod_image_source: archive`: образ собирается на твоей машине,
жмётся (около 10 МБ) и уезжает по ssh. Реестр не нужен, работает с первого дня.

Если появится CI, переключи в `group_vars/svod.yml`:

```yaml
svod_image_source: registry
svod_image_registry: ghcr.io/spudro228
```

## Бэкапы

Ежедневно в 4 утра systemd-таймер кладёт в `/var/backups/svod`:

- снимок базы через `sqlite3 .backup` — копировать файл под нагрузкой нельзя,
  получится рваный слепок
- блобы через `rsync`; они неизменяемы, поэтому докидываются только новые

Снимки базы старше 30 дней удаляются, блобы остаются.

Заметки лежат на каждой машине целиком, поэтому сервер — не единственная
их копия. А вот **история версий существует только на сервере**, и бэкап
нужен прежде всего ради неё.

Проверить руками: `/opt/svod/backup.sh`

## Что где смотреть

```bash
ssh <сервер>
cd /opt/svod
docker compose ps
docker compose logs -f svodd
docker compose logs -f caddy      # сюда же пишутся ошибки выпуска сертификата
systemctl list-timers svod-backup.timer
```
